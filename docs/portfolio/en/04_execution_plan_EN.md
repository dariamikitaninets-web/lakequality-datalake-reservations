# Three-to-four-day execution plan

## Day 1 — understanding and first flow

Review the mission, data flow, acceptance criteria, and risks. Generate synthetic sources, execute the fixed Bronze-to-Gold pipeline, perform manual SQL checks, and capture the first evidence.

**Outcome:** working data flow and a clear explanation of what is tested and why.

## Day 2 — automation and defect lifecycle

Review schema, integration, E2E, and idempotency tests. Run the controlled faulty deduplication, record BUG-001, fix it, retest, and execute the complete regression suite with machine-readable reports.

**Outcome:** failing test → investigation → correction → successful regression.

## Day 3 — CI/CD, performance, and reporting

Run a real CI quality gate, measure controlled data volumes, generate the quality report, and issue an evidence-based GO/NO-GO recommendation.

**Outcome:** automated quality gate and measurable quality assessment.

## Day 4 — optional Kubernetes and portfolio

Execute a Kubernetes Job only if a real local cluster is available. Otherwise, label its manifest as a non-executed proposal. Assemble the bilingual portfolio and rehearse 60-second and two-minute presentations.

**Outcome:** interview-ready evidence without overstating experience.

## Integrity condition

Every screenshot must come from an actual execution. No GitLab, terminal, Kubernetes, or internal-tool interface is recreated.
